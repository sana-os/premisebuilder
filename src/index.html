      Quick start & input example

      1. Create a local project and identify the recorder and decision authority.
      2. Answer a question, then record why, whose perspective it represents, and how it was obtained.
      3. Choose a separate Resolution, review the premise, and confirm a Base revision.

      Example: responsive priority

      Answer: Desktop is the priority.

      Context: Prioritize desktop for entry and review. On mobile, keep reading, progress checks, basic answers, and small edits usable. Japanese text must not cause clipping or unintended horizontal overflow.

      Resolution: Confirmed, using the Project owner contribution, resolved by the Project owner.

      After confirmation, export Base or Unified JSON as a portable backup. An imported legacy file without a recorded confirmation time remains explicitly marked as unknown.

      Privacy boundary

      Your project remains local

      Project names, participants, answers, notes, imported files, and generated contexts are stored only in this browser. Premise Builder has no project-data server, analytics, advertising, tracking, remote fonts, or third-party scripts.

      The public host serves only the application, schemas, and question templates. Clearing site data can remove local work; export is the portable backup.

      Premise as Code

      How exported context should be read

      Fact, View, Care, and Unknown describe the premise. Each contribution separately records its perspective, recorder, speaking role, capture method, authority, and confirmation.

      A contribution is not a confirmed requirement by itself. Unspecified means “do not assume”; proposal-requested permits suggestions but not silent decisions; delegated permits a bounded decision that must be reported.
