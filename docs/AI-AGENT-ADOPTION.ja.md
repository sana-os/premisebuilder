# AIエージェント導入計画テンプレート

ホームの「AIエージェント導入計画」、または `/ja/new/ai-agent-adoption/` から開始します。日本語・英語・スペイン語に対応する12カテゴリ・48問です。

## この質問票が整理すること

「AIエージェントが欲しい」という表現だけでは、回答を作ってほしいのか、外部システムを操作してほしいのか、業務の完了まで任せたいのかが分かりません。また、担当者の作業時間を減らしても、別の担当者の確認・修正工数が増えれば、全体の負担は減っていない場合があります。

そのため、任せたい仕事、効果が出ると考える理由、検証に使う現状値、権限、人の負担を別々に記録します。関係者ごとの回答はContributionに分け、プロジェクトとして採用する前提はResolutionで明示します。

ここでいう「エージェント」は、目標に向けて手順やツールを選び、結果を確認しながら次の行動を決める仕組みを指します。「固定手順の自動化」「決められた業務フローの一部で使うAI」「人が確認する回答・下書き」と比較できるようにしています。製品名や実装方式を先に決める質問票ではありません。

## 質問構成

| カテゴリ | 確認する前提 |
| --- | --- |
| 導入目的・対象範囲 | 誰の仕事か、開始条件、段階、任せない仕事 |
| 現行業務・比較の基準 | 現在の手順、ボトルネック、実績、例外 |
| 期待する効果・根拠 | 優先する効果、因果仮説、目標指標、悪化させない条件 |
| 方式選択・自律性 | 他方式との比較、任せる範囲、自律性の必要性、実現可能性 |
| 関係者・責任分担 | 関係者間の期待差、責任者、確認の体制、人への引き継ぎ |
| 情報源・データの境界 | 正本、データの種類、処理・保持の範囲、情報不足時の対応 |
| 実行できる操作・権限 | 接続先、実行する操作、承認、権限の制御 |
| 文脈・引き継ぎ | 記憶、指示の優先順位、外部内容の扱い、担当間の連携 |
| 失敗・停止・復旧 | 失敗の影響、禁止事項、停止、切り戻し・代替手段 |
| 評価・受け入れ条件 | 評価事例、公平な比較、現在ある根拠、導入・見送り基準 |
| 費用・運用 | 実行環境、総費用、観測、保守・再検証 |
| 導入・見直し | 最初の試行、利用者の習熟、拡大条件、縮小・撤退 |

## 回答・判断の扱い

- 期待する効果、効果が出る理由、自律的な方式が必要だという見立ては、採用後も **View** として保持します。Resolutionの「確定」は採用判断であり、予測した効果が実証されたことを意味しません。
- 現状値や検証結果は、期間、件数、条件、情報源を補足します。「未計測」「未検証」も有効な回答です。
- 選択式には「未決定」「提案を求める」「その他」を用意しています。「その他」は補足が必要です。自由記述も未解決のままにできます。
- この初版では各カテゴリの最終採用判断を決定権者に限定します。現場、技術、保守、セキュリティの見立ては、別々のContributionとして記録できます。
- 外部サービスへの実際の接続、エージェントの実行、認証情報の登録は行いません。シークレットそのものではなく、扱う種類と条件を記入してください。

## レビューで見つける4種類のずれ

| 選択の組み合わせ | 確認すること |
| --- | --- |
| 時間・費用・完了時間を削減したいが、現状値が推定・未計測・未決定 | 何を基準に改善と判断するか |
| 回答・下書きのみを任せるが、変更・送信・発注・権限変更・削除も必要 | 準備までか、実行までか |
| 操作ごとの承認や節目の確認を求めるが、確認体制が未定・不要・未決定 | 誰が確認し、不在時にどうするか |
| 実業務へ直接導入したいが、評価が未実施・選んだ例だけ・未決定 | 最初に影響を与える範囲と導入条件 |

これは選択値による確認のきっかけです。自由記述の内容や全ての矛盾を判定する機能ではありません。警告は回答を自動修正せず、導入の可否を自動認定しません。未回答の項目は、通常の未決定事項として残ります。

## 入力例：問い合わせ対応の下書き

以下は説明用の架空例です。新規プロジェクトへの自動入力や、効果の保証ではありません。

| 項目 | 記録例 |
| --- | --- |
| 任せたい仕事 | 担当者が受けた問い合わせに対し、承認済みFAQの根拠を示した返信案を作る |
| 任せない仕事 | 顧客への送信、返金、契約条件の変更 |
| 現状 | 対象50件では、調査・作成・確認の合計が平均12分。件数と期間は実測記録へリンクする |
| 効果の仮説 | FAQの検索と文章化を支援すれば、担当者の総工数が減るかもしれない |
| 成功条件 | 同程度の問い合わせで、確認・修正込みの平均工数を8分以下にする。誤案内率は悪化させない |
| 権限 | 承認済みFAQを読み、内部の下書きを作る。送信は担当者が行う |
| 情報不足 | 根拠のない回答を埋めず、不足情報と確認先を表示する |
| 評価 | 過去事例で比較した後、範囲を限定して試行する。未知の問い合わせも含める |
| 見直し | 確認工数が増える場合は、対象や方法を見直す。固定検索やFAQ改善とも比較する |

目標値はサンプルです。各組織の実績と許容条件から設定してください。効果を得る人と確認負担を負う人が違う場合は、それぞれの観点を記録します。

## 出力と開発

既存テンプレートと同じく、Baseを明示確定し、Override、Unified、AI Context Markdownを生成できます。JSON内のテンプレートIDは `ai-agent-adoption` です。言語を切り替えてインポートしても、選択値と元の自由記述は保持されます。

質問の編集元は `scripts/generate-agent-questions.mjs`、生成先は `templates/ai-agent-adoption/` です。`npm run check` で3言語の生成、テスト、ビルド、全テンプレートの静的検証を行います。

## 設計時の参考

質問文は本プロジェクト向けに作成したものです。固定ワークフローと自律的なエージェントの違い、単純な方式との比較、評価条件と人の関与については、Anthropicの [Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents) を参考にしました。

用途・文脈、役割、測定、運用後の見直しという観点は、NISTの [AI RMF Core](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/) を参考にしました。この質問票は同フレームワークの全項目を網羅するものでも、適合性を認定するものでもありません。
