# Premise Builder 日本語版クイックスタート

Premise Builderは、回答そのもの（Contribution）と、プロジェクトが採用する前提（Resolution）を分けて記録する、ブラウザ内完結型の要件整理ツールです。入力内容はサーバーへ送信されません。

## 1. 日本語版を開く

ビルド済みサイトでは `/ja/` を開きます。新規プロジェクト画面では、次のように入力できます。

| 項目 | 入力例 |
|---|---|
| Project name | `Premise Builder v0.2 — Japanese Edition` |
| Current phase | `Extension` |
| Project content language | `ja` |
| Recorder label | `Project owner` |
| Recorder role | `Developer` |
| Decision authority | プロジェクトの決定権を持つ場合だけオン |

英語版を使う場合は `/en/` を開きます。画面言語を切り替えても、保存済みJSONの安定IDや選択値は変わりません。

## 2. 回答と出所を入力する

各質問で回答を選び、必要に応じて「コンテキストまたは理由」を入力します。たとえばレスポンシブ方針なら次のように記録できます。

| 項目 | 入力例 |
|---|---|
| 回答 | `デスクトップを優先` (`desktop_priority`) |
| 補足 | 主要な入力・レビュー作業はデスクトップを優先する。スマートフォンでも閲覧、進捗確認、基本回答、軽微な編集は可能にし、日本語の文字量が増えても横方向にはみ出さない。 |
| 回答元 | `Project owner` |
| 記録者 | `Project owner` |
| 回答時の役割 | `Developer` |
| 取得方法 | `直接入力` |
| 権限 | `決定権者` |
| 確認状態 | `本人から直接報告` |

同じ質問に別の利用者やレビュー担当者の観点を追加するときは「観点を追加」を使います。推測を記録する場合は取得方法を「推測」にし、確認状態は未確認として扱います。

## 3. Resolutionを明示する

回答を選んだだけではプロジェクト前提になりません。質問下部の「プロジェクトのResolution」で、次を明示します。

1. Resolutionの状態を選ぶ（確定、暫定、未決定、提案待ちなど）。
2. 採用するContributionを選ぶ。
3. 確定権限を持つ決定者を選ぶ。

不明な項目をAIに推測させたくない場合は、「未解決のままにする」を選びます。

## 4. レビューしてBaseを確定する

「レビュー」で未決定事項、競合、出所を確認し、「Baseリビジョンを確定」を押します。確認ダイアログの後、確定ボタンは無効になり、同じ内容を誤って重複確定できません。回答を変更すると「Base r2として確定」のように次のリビジョンが表示されます。

日時フィールドの意味は次のとおりです。

| フィールド | 意味 |
|---|---|
| `meta.confirmedAt` | そのBaseリビジョンを明示的に確定した時刻 |
| `derivedFrom.baseConfirmedAt` | Unifiedが参照したBaseの確定時刻 |
| `derivedFrom.generatedAt` | Unifiedを生成した時刻 |
| `meta.importedAt` | 現在のブラウザへインポートした時刻 |

旧版ファイルに `confirmedAt` がない場合、`updatedAt` を確定時刻と推測しません。「元の確定時刻は記録されていません」と表示します。

## 5. Exportとバックアップ

「エクスポート」には次の形式があります。

- Base JSON: 明示的に確定した基準文書
- Override JSON: Baseに対する範囲付きの変更
- Unified JSON: Baseへ有効なOverrideを順番に適用した結果
- AI Context Markdown: AIへ渡しやすい説明付きコンテキスト

ブラウザのサイトデータを消すとローカルプロジェクトも消えるため、BaseまたはUnified JSONをバックアップとして保存してください。

## 6. JSON互換性を確認する実例

このリポジトリには、今回実際に42問へ回答して作成したサンプルを `examples/japanese-edition/fixtures/` に収録しています。テストは次を確認します。

- 英語版で作成したJSONを日本語版へインポートし、再構築してもスキーマ、項目ID、選択値、Contribution、Resolution、状態、メモが変わらない。
- 日本語の質問ラベルを使っても、英語版と同じ安定ID・選択値を使う。
- 旧版JSONの欠落したBase確定時刻を捏造しない。
- 今回の42問回答をインポートしても、日本語の補足と全42項目を保持する。

開発環境では次で確認できます。

```sh
npm run check
```
